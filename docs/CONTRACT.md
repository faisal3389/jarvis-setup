# Jarvis demo — shared build contract

> Background (v1). Kept for reference; the current contract is `docs/CONTRACT-v3.md`.

Source: https://www.raycfu.com/guides/personal-jarvis-with-claude (a "personal Jarvis" built from
three scheduled Claude agents + a mission-control page). This is a TEMPORARY DEMO on MOCK DATA.
Every builder must follow this file exactly so the pieces fit. Do not edit this file.

Root (call it `$J`): the project root, which is the working directory (cwd) of every Claude run.
`$J/...` below means a path relative to the project root.

## Hard safety rules (whole demo)
- Nothing real is ever sent, spent, or published. No real email, no Buffer, no network writes,
  no MCP write tools. "Send" and "publish" are SIMULATED by writing files into `$J/outbox/`.
- Agents only read `$J/sources`, `$J/inbox`, `$J/content`, `$J/faq.md`, `$J/logs`, `$J/data`, `$J/queue`.
- All data is fictional. Business name: **"Acme Notes"** (a fictional note-taking app, iOS
  subscriptions + Meta ads). Label it MOCK in the UI.

## Dates
- "Today" for the demo = **2026-11-09** (Monday). "Yesterday" = **2026-11-08**. Timezone America/New_York (-05:00).
- Month-to-date = 2026-11-01..2026-11-08. "Same point last month" = 2026-10-01..2026-10-08.

## bin/jarvis.py CLI (Builder B implements, everyone else uses)
Roles: `scout`, `operator`, `advisor`.
```
python3 $J/bin/jarvis.py status  <role> <idle|running|done|error> [message]  # sets status+updatedAt, appends log line if message
python3 $J/bin/jarvis.py log     <role> <message>                            # appends {t,msg} to log (keep last 50)
python3 $J/bin/jarvis.py publish <role> <payload.json>                       # validates payload keys for role, stores under "payload", status=done, appends log "published"
python3 $J/bin/jarvis.py pending-emails                                      # prints JSON {"count":N,"ids":[...]} — inbox ids not in logs/operator-state.json
python3 $J/bin/jarvis.py mark-processed <email-id> [...]                     # adds ids to logs/operator-state.json
```
Every write regenerates `data/<role>.js` atomically (write tmp, rename) as:
```js
window.JARVIS = window.JARVIS || {};
window.JARVIS.scout = { ...the full data/scout.json object... };
```
Role file shape (`data/<role>.json`):
```json
{"role":"scout","status":"idle","updatedAt":null,"log":[{"t":"2026-11-09T06:47:02-05:00","msg":"Reading RevenueCat export"}],"payload":null}
```

## Metric object (used everywhere a number appears)
```json
{"label":"Revenue yesterday","value":412.5,"display":"$412.50","source":"RevenueCat (mock) · sources/revenuecat.json","date":"2026-11-08","kind":"actual"}
```
`kind` is `actual` | `projection` | `unavailable`. When `unavailable`: `value` null, `display` "UNAVAILABLE".

## Payload schemas (what `publish` validates — required top-level keys)
**scout**: `reportDate`, `dataFor`, `revenue`, `ads`, `traffic`, `alerts`, `unavailable`, `projections`, `reportMarkdown`, `wordCount`
```json
{
 "reportDate":"2026-11-09","dataFor":"2026-11-08",
 "revenue":{"yesterday":M,"mtd":M,"vsLastMonthSamePoint":M,"newSubs":M,"cancellations":M,"netSubs":M},
 "ads":{"spendYesterday":M,"roasYesterday":M,"bestAd":{"name":"UGC-Testimonial-v3","roas":M,"spend":M},"worstAd":{"name":"...","roas":M,"spend":M}},
 "traffic":{"signups":M,"activeUsers":M,"movers":[{"text":"Signups +38% vs 7-day avg","changePct":38,"source":"...","date":"2026-11-08"}]},
 "alerts":[{"level":"urgent","text":"4 failed payments yesterday (avg 1/day)","source":"...","date":"2026-11-08"}],
 "unavailable":[{"item":"Stripe payouts","reason":"No connector and no export in sources/"}],
 "projections":[M],
 "reportMarkdown":"<= 300 words, urgent items first, no advice",
 "wordCount":241
}
```
**operator**: `runAt`, `counts`, `items`, `summaryMarkdown`
```json
{
 "runAt":"2026-11-09T09:13:00-05:00",
 "counts":{"resolved":3,"drafted":2,"escalated":1,"delegated":1,"published":1,"held":1},
 "items":[{"id":"email-004","type":"email","from":"dana@example.com","subject":"Refund please","outcome":"drafted","reason":"Mentions refund — needs owner approval","faqRef":null,"file":"outbox/drafts/email-004.md"}],
 "summaryMarkdown":"Resolved 3, drafted 2 (need you), escalated 1, delegated 1 to Developer, published 1, held 1."
}
```
`type` is `email` | `publish` | `delegation`. `outcome` is `resolved` | `drafted` | `escalated` | `delegated` | `published` | `held`.

**advisor**: `date`, `routineDay`, `recommendations`, `unacted7d`, `skippedUnavailable`, `summaryMarkdown`
```json
{
 "date":"2026-11-09","routineDay":false,
 "recommendations":[{"rank":1,"category":"blocking","action":"One sentence, names the specific ad/customer/PR.","evidence":"Specific numbers from today's Scout report with source+date.","ifIgnored":"Consequence this week."}],
 "unacted7d":[{"date":"2026-11-06","action":"...","daysOpen":3}],
 "skippedUnavailable":["Stripe payouts (UNAVAILABLE) not used"],
 "summaryMarkdown":"..."
}
```
`category` is `blocking` | `outperforming` | `degrading` (the guide's priority order). Exactly 3 recs, unless `routineDay` true.

## Page loading rule (Builder A)
`mission-control/index.html` loads `../data/base.js`, `../data/schedules.js`, `../data/scout.js`,
`../data/operator.js`, `../data/advisor.js` with plain `<script>` tags (must work from `file://` — no fetch),
then every 3 s re-injects them with `?t=<now>` and re-renders on change. `?fixtures=1` loads
`fixtures/*.js` instead. Missing files or `payload:null` must render a clean idle/"awaiting run" state.
